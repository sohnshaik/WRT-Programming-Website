Command-Based Architecture

The framework WPILib uses to structure robot code. Everything in 2974's codebase is command-based. Learn this and the rest of the codebase becomes readable.

The Big Idea

Command-based programming splits robot code into two concepts: Subsystems (the physical hardware and what it can do) and Commands (the actions that use that hardware). Think of it like Lego.

Subsystem
Hardware + capabilities
Represents a physical part of the robot — drivetrain, shooter, intake. Holds the motors and sensors, exposes methods to control them.
Command
An action to perform
Uses one or more subsystems to do something — drive forward, spin up shooter, auto-align. Has a start, a loop, and an end.
Scheduler
The traffic controller
Runs all active commands every 20ms. Handles which commands can run at the same time based on subsystem requirements.
Trigger
What starts a command
A button press, a sensor threshold, a time elapsed. Binds an event to a command in RobotContainer.

Writing a Subsystem

Every subsystem extends SubsystemBase. It has a periodic() method that runs every 20ms — use it for logging, safety checks, or updating SmartDashboard.

java — DriveSubsystem.java
package frc.robot.subsystems;

import edu.wpi.first.wpilibj2.command.SubsystemBase;
import com.revrobotics.CANSparkMax;
import frc.robot.Constants.*;

public class DriveSubsystem extends SubsystemBase {

    // Hardware — private, only this class talks to the motors
    private final CANSparkMax leftLeader;
    private final CANSparkMax rightLeader;

    public DriveSubsystem() {
        leftLeader  = new CANSparkMax(DriveConstants.LEFT_ID,  MotorType.kBrushless);
        rightLeader = new CANSparkMax(DriveConstants.RIGHT_ID, MotorType.kBrushless);
        rightLeader.setInverted(true);
    }

    // Public method — Commands call this to actually move the robot
    public void tankDrive(double leftSpeed, double rightSpeed) {
        leftLeader.set(leftSpeed);
        rightLeader.set(rightSpeed);
    }

    public void stop() {
        leftLeader.set(0);
        rightLeader.set(0);
    }

    // Runs every 20ms — good place to log data
    @Override
    public void periodic() {
        SmartDashboard.putNumber("Left Speed", leftLeader.get());
        SmartDashboard.putNumber("Right Speed", rightLeader.get());
    }
}

Writing a Command

Commands have four lifecycle methods. You don't have to override all of them — just the ones you need.

MethodWhen it runsWhat to put here
initialize()Once, when the command startsSetup — reset timers, set initial state
execute()Every 20ms while command runsThe actual behavior — set motor speeds, read sensors
end(boolean interrupted)Once, when the command endsCleanup — stop motors, reset state
isFinished()Checked after every execute()Return true when the command is done. Return false to run forever.
java — TeleopDriveCommand.java
public class TeleopDriveCommand extends Command {

    private final DriveSubsystem drive;
    private final XboxController controller;

    public TeleopDriveCommand(DriveSubsystem drive, XboxController controller) {
        this.drive = drive;
        this.controller = controller;
        addRequirements(drive); // tells the scheduler this uses DriveSubsystem
    }

    @Override
    public void execute() {
        double left  = -controller.getLeftY();
        double right = -controller.getRightY();
        drive.tankDrive(left, right);
    }

    @Override
    public void end(boolean interrupted) {
        drive.stop(); // always stop motors when command ends
    }

    @Override
    public boolean isFinished() {
        return false; // runs until interrupted (driver releases button, etc)
    }
}

Binding Commands to Triggers in RobotContainer

Commands don't run on their own — they need to be triggered. That happens in RobotContainer.java.

java — RobotContainer.java (excerpt)
public class RobotContainer {

    private final DriveSubsystem drive = new DriveSubsystem();
    private final ShooterSubsystem shooter = new ShooterSubsystem();
    private final XboxController driver = new XboxController(0);

    public RobotContainer() {
        // Default command — runs whenever no other command needs the drive
        drive.setDefaultCommand(new TeleopDriveCommand(drive, driver));

        configureBindings();
    }

    private void configureBindings() {
        // While A button is held: spin up shooter
        new JoystickButton(driver, XboxController.Button.kA.value)
            .whileTrue(new SpinUpShooterCommand(shooter));

        // When B button is pressed: run intake for 2 seconds
        new JoystickButton(driver, XboxController.Button.kB.value)
            .onTrue(new RunIntakeCommand(intake).withTimeout(2.0));
    }
}

Command Compositions

You can chain commands together without writing a new class. This is how most auto routines are built.

java — composing commands
import static edu.wpi.first.wpilibj2.command.Commands.*;

// Run A, then B, then C in order
Command autoSeq = sequence(
    new DriveForwardCommand(drive, 1.5),
    new ScoreCommand(shooter),
    new DriveBackCommand(drive, 1.0)
);

// Run A and B at the same time
Command parallel = parallel(
    new DriveForwardCommand(drive, 2.0),
    new SpinUpShooterCommand(shooter)
);

// Run whichever finishes first, cancel the others
Command race = race(
    new WaitForTargetCommand(vision),
    new WaitCommand(3.0) // timeout fallback
);
